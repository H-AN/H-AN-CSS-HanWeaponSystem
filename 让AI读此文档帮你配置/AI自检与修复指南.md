# HanWeaponSystem 8.4：AI 自检与修复指南

本文供 AI 排查用户的现有配置。字段含义、单位和支持范围见同目录 [AI武器配置指南.md](AI武器配置指南.md)；能够访问源码时，同时读取对应版本的执行代码。目标是定位有证据的问题，提出具体修复，征求用户意见后修改，最后复查。

这是一套 AI 工作流程，不是游戏内诊断命令，也不意味着 AI 无需读取文件就能识别所有故障。无法解析模型、未取得日志或未运行游戏的部分必须如实说明。

## 1. 先问现象和文件位置

开场围绕以下内容分轮询问，已经知道的不用再问：

- 哪把武器：菜单名、发放命令或 `useclassname`？
- 实际现象：无法发枪、买不到、ERROR 模型、声音没播、某个按键没反应、时间不对，还是加载报错？预期是什么？
- 配置目录/服务器 `cstrike` 在哪里，插件是什么版本，最近改了什么？有没有报错日志？

用户只有现象时，先请其提供配置位置或相关文件。AI 能读取本地路径就直接读，不让用户重复贴出可访问的内容；无法访问路径时才请其提供文件内容。不要一开始索要整个服务器。

## 2. 读取真正生效的文件

先读 `HanWeaponData.cfg`，定位对应节点和 `useclassname`，然后按故障读取：

| 现象 | 优先读取 |
|---|---|
| 配置无法加载/所有武器异常 | 实际插件版本、完整报错、主配置及报错指向的配置 |
| 发枪命令无效 | 主配置、命令注册逻辑、是否重新加载插件、玩家存活/队伍限制、武器脚本 |
| 模型/贴图异常 | 主配置、当前瞄准/消音状态配置、模型伴随文件、VMT/VTF、Download.cfg |
| 检视/奔跑无效 | 对应功能配置、主配置关联标识、动画资料和触发条件 |
| 机瞄/侧瞄无效 | ZoomData、模板右键限制、模型/镜片材质、按键绑定 |
| 换弹/声音异常 | 主配置、EmptyReloadData、武器脚本 clip_size、音效文件和事件帧 |
| 购买/出售异常 | BuyData 全局及武器节点、主配置、脚本 WeaponPrice、队伍/时间/金钱条件 |
| Bot 不获取/不做动作 | BotData 全局及武器节点、主配置、脚本 bucket、对应动作功能配置 |

核实是在编辑服务器实际使用的配置，还是仓库 `配置示例/`、备份、另一台服务器或另一个 SourceMod 目录。仅修改示例文件不会改变正在运行的服务器。

## 3. 静态自检顺序

### A. 语法和文本

对全部相关 KeyValues 文件实际做语法检查：能用可靠的 KeyValues 解析器时优先用；没有解析器时用理解引号、注释、转义和嵌套的检查方法，并说明其限制。不能只数左右括号就宣称解析通过。

- 检查大括号配对、层级、引号闭合、键后有值或子节点、根节点名称。
- `//` 注释和字符串内的 `{`、`}` 不应作为结构统计；空格及中文显示名本身不是错误。
- 按实际 KeyValues 的转义模式解析，不能直接套用 JSON/C 字符串规则。本插件创建的 KeyValues 默认未开启反斜杠转义；原版 C4 模板的字体 `character` 可以是单个反斜杠，不要把它误判为缺引号后自动“修复”。
- 查找中文引号、全角标点误入关键语法、将 JSON 的冒号/逗号放到 KeyValues 键值之间、把多个完整根节点拼接等问题。
- 检查重复节点、同节点重复字段；指出发生在哪一层，不依赖“解析器可能取第一个/最后一个”侥幸运行。
- 报告实际文件路径、可定位的行号、原始片段及错误原因。行号需来自本次读取，不能编造。
- `Download.cfg` 单独按逐行路径格式检查，不能用 KeyValues 根节点规则检查它。

### B. 武器关联和字段

- 主配置的 `classname` 是否是可创建的原版模板，`useclassname` 是否与实际脚本名和各模块关联一致。
- 重新核对用户要的主武器/副武器/刀/手雷、实际实体模板及脚本 `bucket` 是否一致；不能仅改 bucket 修复模板选择错误。
- `command` 和 `useclassname` 是否唯一，有无大小写/拼写/前后空格差异。
- 子配置节点名是否与主配置一致；错误节点名可能导致同步追加另一个默认关闭节点。
- 是否将开关填在错误文件、错误层级，是否把 `reloadseq` 写成不存在的 `tacticalreloadseq`，或把 `knowback` 写成其他拼法。
- 已启用功能是否具备必需的模型、序列、正数时间；未知字段被忽略不代表功能已生效。
- 对照实际读取代码检查范围和单位：帧/秒、30fps/`reloadfps`、整数/浮点、概率/权重、倍率/绝对值。
- `damage "40"` 是加 40，不是设为 40；乘法应使用 `*`。`firespeed "1"` 不代表正常或 1 秒间隔；`reloadspeed "2"` 会让普通换弹更慢。
- 弹匣容量查脚本 `clip_size`，`ammo` 查发放备弹用途；不能用其中一个修补另一个。`ammo` 省略时当前默认 20000。
- 无弹药机制检查 `primary_ammo/secondary_ammo` 的 `None` 与无弹匣 `clip_size -1`；`clip_size "None"` 是错误类型。手雷需要保留其消耗数量的弹药类型，不因没有弹匣就清成 `None`。

### C. 模型、路径和下载

- 相对路径是否正确；声音字段不含 `sound/`，下载表声音包含 `sound/`；文件大小写是否与服务器匹配。
- 检查实际引用的 V/W/瞄准/消音模型及必要伴随文件，模型格式和基础模板动画布局是否匹配。
- 原版替换包转独立武器后，检查模型改名时是否漏掉同 basename 的 VVD/VTX 等文件，脚本与配置是否仍指向旧路径；材质、模型包含/动画或声音内部引用是否没有同步。按 [模型独立化与安装包.md](模型独立化与安装包.md) 排查，不能只补一个新文件名就宣称完成独立化。
- 能可靠解析时检查序列索引存在、皮肤索引合法；奔跑的 `runseq+1` 是否仍是正确奔跑动作。不能仅凭 MDL 文件存在就断言动画正确。
- 模型材质路径、VMT 引用纹理、共享资源和 `_rt_camera` 镜片是否齐全。原版打包资源可通过游戏搜索路径提供，需区别于真正缺文件。
- 已上传服务器但未进下载表、已进下载表但服务器没文件、FastDL 没上传、客户端未刷新，属于不同情况，应分别取证。
- `Download.cfg` 的引号、错误根节点、整行后附注释、全盘大目录和未支持的 `.txt` 项要单独检查；下载表并不会复制文件。

### D. 状态、按键和生效时机

- 主配置新增后是否重新加载插件、玩家是否重新取枪；脚本是否被插件/引擎缓存；新下载项是否经历地图开始流程。
- 检视默认 F/`sm_inspect`；侧瞄默认需要 `bind mouse3 +attack3`；奔跑是点按 Shift 后保持前进，不是一直长按 Shift。
- 检视受攻击冷却、换弹、瞄准/奔跑、自定义动画不可打断模式等限制；不要把预期中的限制当作配置错误。
- `awp/scout/m4a1/usp/glock/famas` 模板的原版右键占用、插件机瞄与自动连发之间的限制需要结合代码判断。
- Buy/Bot 的全局开关与本武器开关分别检查；Bot 给予权重为 0、脚本缺 bucket、金钱不足/队伍不符或对应动作功能没开启，都不能靠提高一个行为概率解决。
- 怀疑其他插件覆盖动画或攻击时间戳时，先取得插件列表、日志或可复现步骤，将其列为待验证原因；未经用户同意不批量停用插件，也不擅自改攻击冷却绕开限制。

## 4. 针对常见问题的定位要求

| 现象 | 优先排除，不直接下结论 |
|---|---|
| 按 F 没反应 | `inspect` 是否开启、seq/time 是否有效、useclassname 是否匹配、8.4 冷却门槛、是否处于禁止检视状态 |
| 奔跑播到奇怪动作 | `runseq+1` 是否指到别的动作、runtime 单位是否错、过渡序列是否确实存在 |
| 换弹没声音 | 脚本是否读到正数 clip_size、当前弹匣/备弹条件、该模式的声音来源、路径、事件帧、预缓存和下载 |
| 满弹匣按 R 播音效 | 实际脚本 clip_size 与武器容量是否一致、实际加载的脚本缓存、音效是否来自其他插件/模型事件；不能改主配置 ammo 冒充修复 |
| 声音太早/太晚 | 事件帧、模型 FPS、reloadfps、reloadspeed 与计时接管是否混用；检视声音仍按 30fps |
| 有两个枪声/换弹声 | 自定义声音与脚本/模型/其他插件是否重复播放；先确认来源，不批量删除声音 |
| 右键没有机瞄 | 基础模板右键限制、zoom 开关、模型、当前状态；不是看到 zoom 1 就认定源码坏了 |
| 狙击镜黑屏 | 镜片材质、_rt_camera、FOV 设置、资源分发和模型 skin 布局；不随机修改 skinadd |
| 菜单没有这把枪 | buysystem/buyable、主配置注册是否成功、useclassname、队伍、购买时机等过滤条件 |
| Bot 不拿这把枪 | botsystem、botchance、脚本 bucket、候选槽位、金钱模式和队伍过滤 |

## 5. 先报告，再征求用户意见

用简短表格或列表报告每个问题，区分：

- **已确认错误**：给出文件位置、实际值、代码规则或解析错误和直接影响。
- **疑似原因**：给出依据以及还需什么信息/操作才能验证。
- **无需修改**：例如功能明确关闭、缺少可选资源但没有引用、满弹匣本来就不应换弹。

提出具体修复内容，让用户能判断后再询问意见。例如：

```text
已确认：HanWeaponInspectData.cfg 的该武器 inspecttime 为 0，开启检视也无法开始。
你提供的模型资料显示检视时长为 2 秒，应填 60（30fps 基准）。
建议只将该武器的 inspecttime 从 0 改成 60，保留其他设置。
是否按这个方案修改？
```

如果没有可靠时长，不能套用示例里的 60；应询问动画资料或是否暂时关闭检视。存在多个合理选择时，用效果说明选项，而不是替用户决定玩法。

用户同意具体方案后再修改；若用户已经明确授权同一方案，不重复确认。等待意见时可以继续只读核验其他项目。不能在用户回答前把“建议修复”当作已授权修改。

## 6. 修改后复查和交付

1. 备份被修改文件，执行用户认可的最小修改，保留其他武器与全局设置。
2. 重新读取修改后的实际文件，复查语法、关联、路径及此次错误。把真实差异与方案比对，避免修改到另一把同名显示武器。
3. 给出修改位置、原值/新值、备份位置，以及还需要用户执行的重载、重新取枪、换图/服务器重启等步骤。
4. 报告分开写：哪些文件检查已通过、哪些资源还不能确认、哪些效果已游戏内验证、哪些尚未实测。不能把“无语法错误”说成“问题已经全部解决”。
5. 若静态配置正确但现象仍在，收集一次明确复现：插件版本和加载列表、对应日志、当前武器/队伍、按键顺序、是否空弹匣及是否有备弹、最近重载/换图情况；按证据继续定位源码、引擎缓存或插件冲突，不反复重写全部配置。
