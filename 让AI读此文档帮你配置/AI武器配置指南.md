# HanWeaponSystem 8.4：AI 武器配置指南

本文供 AI 阅读并执行。目标是帮助用户把一把武器配置完成：先读取资源和现有配置，分轮询问真正缺少的信息，再直接生成或修改所需文件，并提供测试步骤。不要只解释字段后让新手自己填写。

本指南依据本仓库 8.4 源码整理。若用户使用其他版本，先核对其版本和对应实现。源码与旧注释、README 或示例冲突时，以用户实际版本的执行代码为准；无法取得源码时，明确说明尚不能确认的版本差异。

用户报告“配置失败”“某个功能没效果”时，转到同目录的 [AI自检与修复指南.md](AI自检与修复指南.md)。不要重新生成全部配置来掩盖故障。

本目录已附带 [29 份武器脚本模板及选用说明](原版武器脚本模板/说明.md)。模型原本用于替换原版武器、需要独立改名或需要生成离线安装包时，同时读取 [模型独立化与安装包.md](模型独立化与安装包.md)。分发时携带整个目录，不能只把作者电脑上的模板来源路径告诉其他用户。

## 1. 与用户交流和处理缺失资料

1. 先读能访问的文件，再提问。用户给出的路径只代表位置；路径不可访问时说明缺少文件访问能力，请用户提供相关文件内容或资源包，不能声称已经读过。
2. 每轮围绕一个主题，通常问 1～3 个简短问题。用“要不要按 F 看枪”“奔跑只换动作，还是也加速”等玩家能理解的表达，再由 AI 转成字段。
3. 维护一份简短记录：已经从文件确认的信息、用户选择、尚缺的信息。用户已经回答的不要重复问。
4. “不知道”不是“关闭”。先尝试读取资料，再告诉用户去哪里看；需要取舍时，让用户选择补资料或暂时关闭该功能。
5. 不凭文件名猜动画序号、帧数、FPS、皮肤索引、声音事件帧、脚本内容和材质依赖。能读取二进制模型不等于已经解析模型；需要可靠的模型解析工具、QC/SMD 等资料或模型查看器数据。
6. 用户选定的功能，相关必需信息齐全后才能开启。缺少可选功能资料时可先完成其他部分，但要标明未完成项；不得把缺资料的功能写成已配置成功。
7. 基础武器模板、目标配置位置、实际资源路径等影响结果的信息不能随意决定。普通平衡值可向用户提出默认方案；用户接受“按默认”后直接执行，不逐字段反复确认。
8. 普通配置不能创造模型里没有的动画，也不能凭配置增加新弹道、技能、连招伤害或全新开火模式。发现需要改模型、武器脚本或额外插件时，具体解释缺哪一部分。

## 2. 开始时先确定环境并盘点文件

优先从用户提供的位置查找以下内容；范围先限定在目标服务器、指定资源包和本仓库，不扫描无关磁盘。

| 内容 | 要确认什么 |
|---|---|
| 服务器游戏根目录 | 是实际 `cstrike/`，不是 `addons/sourcemod/`；配置路径由此推导 |
| 已安装插件 | HanWeaponSystem 版本、是否有其他接管同一武器的插件 |
| 现有配置 | `addons/sourcemod/configs/HanWeaponSystem/` 下现有文件、根节点、全局开关、已有命令和武器标识 |
| 资源包 | `models/`、`materials/`、`sound/`、`scripts/`；包内是否多套模型、多把武器或压缩文件 |
| 资源原用途 | 是否是覆盖原版路径的替换包，是否需要另建名称、目录及内部资源引用 |
| V 模型 | 正常第一人称模型、模型格式及动画布局是否与基础武器相符 |
| W 模型 | 手持、掉落等世界模型；若缺失，询问补充还是接受沿用已确认可用的原版模型 |
| 武器脚本 | `cstrike/scripts/<useclassname>.txt`；应是 `WeaponData` 结构 |
| 瞄准模型 | 机瞄、侧瞄是否有适用模型；同一 MDL 也可以，必须有其确实支持对应视角的依据 |
| 动画资料 | 序列索引、名称、时长、实际 FPS；必要时查看不同瞄准/消音状态的模型 |
| 音效与材质 | 声音文件、动画事件、模型材质搜索路径、VMT 引用的纹理及共享依赖 |

不要把 `scripts/weapons/` 下的声音定义文件当成 `scripts/weapon_xxx.txt` 武器数据脚本。只有加密脚本且不能可靠读取时，请用户提供可编辑版本或确认采用哪个可用模板，不编造解密结果。

模型依赖要核对同名 `.vvd`、`.dx90.vtx` 等实际所需伴随文件；`.phy`、外部动画等按模型实际引用检查。不要只复制 `.mdl`，也不要把未使用的可选伴随文件缺失一律判为故障。原版资源可能由游戏搜索路径或打包资源提供，不等于必须在自定义资源包中找到同名文件。

如果有本仓库源码，可按需查阅这些文件，不必把整个项目全文发给用户：

| 问题 | 对应源码（相对仓库根目录） |
|---|---|
| 版本、主配置、脚本缓存 | `HanWeaponSystem/HanWeaponSystemGlobals.inc`、`HanWeaponSystemConfig.inc` |
| 发枪、备弹 | `HanWeaponSystem/HanWeaponSystemWeapon.inc` |
| 伤害、攻速、普通换弹速度 | `HanWeaponSystem/HanWeaponSystemCombat.inc` |
| 瞄准/检视/奔跑/换弹 | `HanWeaponSystem/` 内对应模块及其 `*Config.inc` |
| 音效、下载 | `HanWeaponSystem/HanWeaponSystemSounds.inc`、`HanWeaponSystemDownload.inc` |
| 购买、Bot | `HanWeaponSystem/` 内 `Buy`、`Bot` 及对应配置模块 |
| 自定义动作与 API | `HanWeaponSystem/HanWeaponSystemCustomAnim.inc`、`include/HanWeaponSystem.inc` |

上表同一行省略目录的文件仍位于 `HanWeaponSystem/` 内。可对照 `配置示例/`，但示例参数属于示例武器，不能照搬为用户模型的数据。

## 3. 分轮询问流程

### 第一轮：先确认类型、弹药机制和输出位置

用户说“加一把武器”时，必须先确定以下三个问题，再进入具体功能配置。若用户已经明确回答，概括确认即可，不重复问；“枪的外观”不能代替实际类型与机制。

1. **武器类型**：“这是主武器、副武器、刀，还是手雷？”用户说步枪、手枪等明确类别时可对应归类；特殊装置需问实际占哪个槽位。手雷还要问 HE、闪光、烟雾中的哪种基础行为；C4 仅在用户明确需要时单独处理。
2. **弹药机制**：“它像普通枪一样有弹匣并换弹，还是不消耗弹药的特殊武器？也可能没有弹匣但会消耗数量，例如手雷。”区分暂时打空、无限备弹、不消耗弹药和无弹匣消耗数量，不能只问含糊的“有没有子弹”。
3. **输出位置**：“有服务器 `cstrike` 目录吗？有就提供；没有也可以，我会生成独立安装包。”没有服务器目录不是阻塞项，不要求用户先搭服务器，也不停止生成配置和资源。

记录显示名称、V/W 模型或完整资源包位置；先读取再判断是否沿用原版名称/路径。选一个唯一的英文武器标识供脚本、模型目录和配置使用，由用户已有命名或其接受的方案确定。

然后按类型询问合适的原版 `classname` 模板。类型名称不足以唯一确定模板时，给出同类型候选并说明右键、开火方式、换弹等差别，让用户选定。不能只改脚本 `bucket` 就承诺把一个主武器实体变成副武器，实体模板、脚本和用户想要的槽位必须相符。

### 按类型分流，而不是给所有武器同一张问卷

| 用户选择 | 模板/脚本槽位 | 优先询问与配置 | 默认不询问或不启用 |
|---|---|---|---|
| 主武器 | 匹配的步枪、冲锋枪、机枪、狙击枪或霰弹枪模板；通常 `bucket 0` | 弹药机制、弹匣/备弹、射击与拔枪声、适用的换弹、检视、奔跑、机瞄/侧瞄、购买/Bot | 刀距离、刀音效目录替换、手雷飞行模型缩放 |
| 副武器 | 匹配的手枪模板；通常 `bucket 1` | 弹药机制、弹匣/备弹、射击与拔枪声、适用的换弹、检视、奔跑、可选瞄准；USP 等还需考虑原版右键 | 刀/手雷专用字段；不能默认所有手枪都可插件右键机瞄 |
| 刀 | 通常 `weapon_knife`、`bucket 2` | 必须询问刀音效是否替换、CT/T 是否相同，核对挥空/命中/重击等文件；左右键距离、检视、奔跑、拔刀声、购买/Bot | 普通枪弹匣、装填、枪械射击声和枪械精度；技能/连招不是普通配置自动生成 |
| 手雷 | 用户选定的 `weapon_hegrenade/weapon_flashbang/weapon_smokegrenade`；`bucket 3` | 数量/消耗方式、V/W 及飞行相关模型、拉保险/弹跳/爆炸声音、前缀目录、飞行缩放、资源下载；检视/奔跑按模型与需求选择 | 枪械弹匣/换弹、枪械射速与精度、刀距离；不能将手雷误设成完全无弹药 |
| 不消耗弹药的特殊武器 | 这是独立于上述槽位的机制；先选实际需要的模板和槽位 | `primary_ammo/secondary_ammo`、`clip_size`、攻击间隔、声音、模型动作，以及是否依赖额外功能插件 | 普通弹匣、备弹、空仓/战术换弹；不要因长得像枪就自动开启 |

检视、奔跑、购买/Bot 是可按实际需要询问的功能，不因外观或类别自动开启。特殊机制可以覆盖某些默认项，但必须有用户需求和当前模板/插件支持的依据。

### 选模板并生成独立武器脚本

必须区分三个名称：

| 名称 | 含义和约束 |
|---|---|
| 主配置节点名 | 推荐与 `useclassname` 相同；所有子配置采用一致节点名以便同步 |
| `classname` | 引擎创建用的真实原版类，如 `weapon_ak47`、`weapon_m249`、`weapon_knife`；不能随意改成新名字 |
| `useclassname` | 新武器标识，如 `weapon_my_rifle`，对应 `scripts/weapon_my_rifle.txt`，各模块必须一致 |

先查是否有配套武器脚本。没有时无需让新手自己寻找或编写：读取本目录附带的 `原版武器脚本模板/scripts/weapon_*.txt`，让用户从合适的基础行为中选择；确定 `classname` 后，复制对应完整模板为 `scripts/<useclassname>.txt`，由 AI 修改模型路径、弹匣容量、弹药机制及用户要求的字段。保留其他模板字段和子节点，不覆盖库内原件，也不将整套原版模板安装进服务器。

仅当随附模板目录也未提供、不可访问，且没有其他可用基础脚本时，才请用户补充模板文件或整个文档目录。作者本机的 `D:\css\移动\css武器原版脚本\css_weapons_txt_1592011\cstrike\scripts` 只是来源记录，不能当其他用户电脑上必然存在的路径。

向用户明确说明：**弹匣容量修改新武器脚本的 `clip_size`，发放备弹才使用主配置 `ammo`。** 若用户希望“不消耗弹药”，一般将脚本 `primary_ammo` 设为 `None`，无副弹药时 `secondary_ammo` 也设为 `None`，无弹匣用整数 `clip_size "-1"`；`default_clip` 保留/按模板机制核对，不能填 `None`。普通枪不能仅靠把主配置 `ammo` 设为 0 达到无弹药机制，`clip_size` 也不能写成字符串 `None`。

刀、手雷原模板均可能 `clip_size -1`，但手雷 `primary_ammo` 保留对应数量类型；`-1` 不等于不消耗任何资源。特殊枪械模板是否在这些字段调整后仍能正确攻击，需按其实际开火实现及额外插件验证，不承诺“随便选模板再写 None”就一定实现特殊武器。

为新武器选择未占用的 `useclassname` 和 `command`。普通发放命令没有管理员权限检查，知晓命令的玩家可以免费取枪；问清楚是便于测试的直接发放，还是通过购买/其他系统获取，不把随机命令名描述成权限控制。

### 第二轮：功能选择

先按上面的类型和弹药机制筛选，再分几轮询问适用项；例如刀必须问专用声音，完全无弹药特殊武器不机械询问普通换弹：

- 检视：要不要按 F 检视？能否反复按 F 重播？是否屏蔽手电光？
- 奔跑：模型是否有奔跑动作？只播放动作还是还要加速？是否有起手、收尾和晃动？
- 机瞄/侧瞄：想用右键机瞄、中键侧瞄中的哪种？是否需要镜片内放大？是否有适用模型？
- 换弹：空弹匣与还有子弹时是否使用不同动画？是否要按模型时长接管换弹？
- 声音：射击、拔枪、换弹、检视是否有自定义声音？是否需按动画帧触发？
- 变体：模板是否支持消音器？装上/卸下后的模型、序列和声音是否不同？

每确认一个功能，再收集它需要的数据。不要一开始把所有技术字段抛给用户。

### 第三轮：收集动画和事件数据

优先读取可靠的模型资料。无法解析时，让用户在 HLMV 等工具里打开对应模型，提供序列索引、序列名、帧数、FPS 或实际播放秒数；声音还需对应事件帧。序列按实际索引填写，通常从 0 起，不把列表第几个当成序号。

只有 `inspect`、`run` 等名字不能证明用户要的是哪段动画；存在多个候选时，应给出候选及用途供选择。资料齐全时由 AI 换算，不要求用户自己做算术。

### 第四轮：弹药、平衡、获取和 Bot

对有弹匣/弹药的武器问清楚弹匣容量、发放时备弹；对无弹药武器跳过不适用项。再按类型询问伤害/攻击间隔、后坐力、普通换弹速度、队伍限制、购买价格和 Bot 行为。刀音效与距离、手雷声音/飞行模型等要在对应分支主动询问，不能隐藏在只有熟练用户才会要求的高级项中。

用户选择保持原样时，用中性配置值，不照搬示例的 `damage +40`、超大备弹、加速或 Bot 概率。读取已有全局设置，新增武器不能意外改变其他武器的行为。

## 4. 文件结构和路径约定

运行时配置目录：`cstrike/addons/sourcemod/configs/HanWeaponSystem/`。

| 文件 | 本次武器应处理的内容 |
|---|---|
| `HanWeaponData.cfg` | 发放命令、模板、标识、基础模型、声音和平衡值 |
| `HanWeaponZoomData.cfg` | 机瞄和侧瞄；不启用则对应开关为 `0` |
| `HanWeaponInspectData.cfg` | 检视；不启用则 `inspect 0` |
| `HanWeaponRunData.cfg` | 奔跑；不启用则 `run 0` |
| `HanWeaponEmptyReloadData.cfg` | 空仓和战术换弹；分别明确开关 |
| `HanWeaponBuyData.cfg` | 本武器的购买、出售和显示名；保留全局设置 |
| `HanWeaponBotData.cfg` | 本武器给予权重、行为概率；保留全局设置 |
| `Download.cfg` | 本武器实际需要的下载文件/目录，去重追加 |

除 `Download.cfg` 外，这些配置的根节点都是 `"HanWeaponSystem"`。在原根节点内合并本武器节点，不能把多个完整根节点直接拼在一起。子配置武器节点里填写同一个 `useclassname`。同步逻辑以节点名查缺追加，不会自动理解用户需求，也不会替你修正已有错误标识。

武器脚本位于 `cstrike/scripts/<useclassname>.txt`，根结构为 `WeaponData`，不是 `HanWeaponSystem`。

路径规则：

| 用途 | 示例写法 |
|---|---|
| 模型字段 | `models/weapons/my_rifle/v_my_rifle.mdl` |
| 声音字段 | `weapons/my_rifle/fire.wav`，不含 `sound/` 前缀 |
| 下载表中的声音 | `sound/weapons/my_rifle/fire.wav`，含 `sound/` 前缀 |
| 下载表中的模型/材质 | `models/weapons/my_rifle`、`materials/models/weapons/my_rifle` |

配置统一使用 `/`、英文引号和英文逗号。不要填 Windows 绝对路径、把 `cstrike/` 再写入资源路径，或擅自改资源大小写。目标是 Linux 服务器时还要检查大小写完全匹配。

### 原版替换包转独立新武器

用户下载的资源若沿用 `models/weapons/v_rif_ak47.mdl` 等原版名称/路径，新增武器时必须按 [模型独立化与安装包.md](模型独立化与安装包.md) 创建独立目录、独立模型名、伴随文件和相应配置/脚本引用，不把替换包直接覆盖到原版位置。材质、声音有同名冲突时也需处理内部引用，不能只改最外层 MDL 文件名就宣称全部完成。

## 5. 字段规则：按实际执行代码配置

### 5.1 主配置和脚本

| 字段/位置 | 处理规则 |
|---|---|
| `command` | 唯一、不与已有命令冲突；普通可用发枪流程需要注册命令 |
| `classname` / `useclassname` | 按第 3 节区分；不能只改其中一个关联文件 |
| `vmodel` / `wmodel` | 使用已确认可用的模型路径；W 模型缺失先提出补充/沿用方案 |
| `team` | 使用 `all`、`ct`、`t`；不要混入脚本的 `ANY` 写法 |
| `damage` | 空值不调整；`+40` 加 40，`-10` 减 10，`*1.5` 乘 1.5，`/2` 除 2；裸数字按加法。旧注释中的 `x1.5` 不符合当前乘法分支，不使用。脚本 `Damage` 才是基础值，二者不要重复叠加 |
| `firespeed` | `0` 或 `*1` 为正常；`*2` 或 `+1` 为两倍攻速；`/2` 为半速。`左:右` 可分别设置；单值会用于两侧。它调整攻击冷却，不是“填写几秒”，也不等于改变动画 FPS。优先使用明确的 `*`、`/` 写法 |
| `recoil` | `1.0` 中性，`0` 清除后坐力；按用户需求设置 |
| `reloadspeed` | 普通换弹时长系数，`1.0` 正常、`0.5` 更快、`2.0` 更慢；不是“2 就两倍快” |
| `knowback` | 原字段拼写如此，不改成 `knockback`；无需求时省略/使用中性值 |
| `ammo` | 仍在使用的发放弹药参数：传给实体 `ammo` 键，并将该类型备弹至少补到此值。它不代表弹匣容量，也不参与满弹匣判断；省略时当前默认 `20000`，因此必须让用户知道备弹方案，不以为留空就是沿用脚本 |
| 脚本 `clip_size` | 弹匣容量，用户要求几发就改新武器脚本中的此项；无弹匣通常填整数 `-1`，不是 `None`。插件读取它缓存最大弹匣值，配合实际 `m_iClip1` 和备弹判断是否播放换弹音效。脚本缺失或容量为非正数，相关换弹音效判断会受影响 |
| 脚本 `CycleTime` / `Damage` | 对适用模板提供基础开火间隔/伤害；保留模板所需其他字段，插件攻速/伤害设置可能进一步调整 |
| 脚本 `primary_ammo` / `secondary_ammo` | 弹药类型；完全无弹药的对应项用 `None`，和 `clip_size -1` 分开判断。手雷虽然无弹匣，仍需对应的计数型弹药；不能机械清成 `None` |
| 脚本 `bucket` / `WeaponPrice` | Bot 槽位和价格回落会读取；不能漏掉或放到错误层级 |
| `killicon` | 击杀图标映射，按可用的原版图标或已实现资源配置；不是菜单显示名 |
| `autofire` | 按住右键转主攻击连发并清后坐力；不是普通左键全自动开关。与插件机瞄或原版右键占用存在限制，默认不启用 |
| `Sqtype` | 特殊动画同步模式，只有确认当前模型需要时设置；不能把它当“启用检视/奔跑”的总开关 |
| `skincode` | 模型实际存在的 skin 索引，不能编造皮肤数 |
| `usedroppedmodel` | 是否用假 W 模型处理掉落；根据资源和测试选择 |
| `armfix` / `shootqcfixes` | 对应手臂、开火动画修复；按症状启用，不把所有修复开关默认打开 |
| `grenadescale` | 仅手雷飞行模型缩放；没有需求就省略，不会改变爆炸范围或伤害 |

### 5.2 检视

`inspect 1` 必须有有效 `inspectseq`（可为 0）及正数 `inspecttime`。

| 字段 | 数据和默认方案 |
|---|---|
| `inspectseq` | 用户确认/可靠读取的序列索引 |
| `inspecttime` | 时长，单位是 30fps 基准帧数：`秒数 × 30`；整数换算说明取整方式 |
| `inspectrepeat` | `0` 不重播，`1` 可反复按 F 重播；询问用户 |
| `inspectflashlight` | `1` 屏蔽手电光，`0` 不屏蔽；询问用户 |
| `inspectsound` | 可空；普通路径用逗号分隔随机选一个，`帧号:路径` 用于分段定时声音；定时帧同样按 30fps，不是模型任意 FPS |

8.4 的检视门槛看玩家 `m_flNextAttack` 和武器主攻击时间戳；刀、配置右键连发或自动连发的武器还看副攻击时间戳，不看弹药数量。冷却结束且未换弹时可打断允许中断的自定义动画，`interruptable=false` 仍受保护。不要试图通过改检视时长修复攻击冷却，也不因此修改用户原有攻速。

### 5.3 奔跑

`run 1` 需要有效 `runseq` 和正数 `runtime`。系统交替播放 `runseq` 与 `runseq + 1`，必须核对这两个连续序列都是正确动作，不能只确认一个奔跑序列就启用。

| 字段 | 处理规则 |
|---|---|
| `runseq` / `runtime` | 第一段序列索引和一次切换间隔；时间按 30fps 基准帧数 |
| `runin` / `runinlength` | 可选起手序列/时长；没有时使用 `-1`/`0` 或省略，不编造 |
| `runout` / `runoutlength` | 可选收尾序列/时长，同样按 30fps |
| `runspeed` | 每 tick 叠加的水平推力，不是固定移动速度；只播放动作时可用 `0` |
| `runmaxspeed` | 加速上限；启用推力时应有用户认可的上限，不把 `0` 当默认限速 |
| `runshake` | 晃动强度；无需求用 `0`，不要把示例强度当模型必需值 |

操作是点按 Shift 后继续按前进；长按 Shift 保留静步。时长不能填秒数。缺少第二段连续序列属于模型/动作布局问题，单靠添加 `runseq2` 等不存在的字段无法解决。

### 5.4 机瞄和侧瞄

两套参数放在 `HanWeaponZoomData.cfg`。机瞄前缀为 `zoom`，侧瞄前缀为 `sideaim`。

| 字段 | 含义和约束 |
|---|---|
| `zoom` / `sideaim` | 各自独立的开关 |
| `zoommodel` / `sideaimmodel` | 适用的瞄准模型；正常模型直接复用需有其支持该视角的依据 |
| `zoomanimmove` / `sideaimanimmove` | 可选衔接序列，无衔接用 `-1`；当前执行分支要求序列 `>0` 且时间 `>0` 才播放衔接 |
| `zoomanimtime` / `sideaimanimtime` | 单位为秒，进入/退出都会使用，不是帧数 |
| `zoomanimfire` / `sideaimanimfire` | `1` 在完全瞄准时不强制同步开火动作；无特殊需求用 `0` |
| `zoomfov` / `sideaimfov` | `90` 不启用镜片内放大；`0<FOV<90` 需对应 `_rt_camera` 镜片材质支持，不能只填数字就承诺有瞄准镜 |
| `zoomaccuracy` / `sideaimaccuracy` | `-1` 不修改；当前代码仅对 `(0,1)` 范围生效，`0` 不能当“完全无散布” |
| `zoomspeed` / `sideaimspeed` | `1.0` 不减速，`(0,1)` 范围减速；大于 1 不能当作瞄准加速 |
| `zoomcrosshair` / `sideaimcrosshair` | `1` 隐藏准心，`0` 不隐藏 |
| `zoompunch` / `sideaimpunch` | 震屏系数，`1.0` 中性 |
| `zoomskinadd` / `sideaimskinadd` | 非镜内放大时使用的皮肤增量；需确认模型 skin 布局，无需求用 `0` |

8.4 代码将 `awp/scout/m4a1/usp/glock/famas` 模板视作原版右键占用，插件右键机瞄不生效；需要对应自定义瞄准时，考虑已有中键侧瞄或经用户确认重新选择合适模板，不擅自换掉武器基础类。侧瞄需提醒执行 `bind mouse3 +attack3`。

### 5.5 空仓、战术换弹和声音

| 字段 | 含义 |
|---|---|
| `emptyreload` / `emptyreloadseq` / `emptyreloadtime` | 空弹匣换弹开关、序列、时长帧数 |
| `tacticalreload` / `reloadseq` / `reloadtime` | 还有子弹时换弹开关、序列、时长帧数；没有 `tacticalreloadseq` 这个字段 |
| `reloadfps` | 换弹帧率，正整数，缺省 30；在本换弹配置里，不是主配置的 FPS 总开关 |
| `emptyreloadsound` / `tacticalreloadsound` | 分别对应空仓、战术换弹声音 |
| 主配置 `reloadsound` | 未启用相应换弹接管时的兜底声音 |

声音格式为 `10:weapons/my_rifle/magout.wav,45:weapons/my_rifle/magin.wav`。数字是确认过的事件帧，不是秒，不填 `sound/`。启用某一换弹模式后，该模式声音没填不会自动改播主配置兜底声音。

计时规则务必分清：

| 项目 | 实际换算 |
|---|---|
| 检视、奔跑和它们的帧时长 | `配置帧数 / 30`；若源动画是 24fps、48 帧，即 2 秒，应填 60 个基准帧 |
| 瞄准衔接 | 直接填写秒数 |
| 空仓/战术换弹计时接管 | `timeFrames / reloadfps`；普通弹匣武器接管时强制播放率 1.0 |
| 换弹声音调度 | `事件帧 × reloadspeed / reloadfps` |

接管换弹时不要再盲目叠加 `reloadspeed` 以为动作时长与声音都会一起缩放；无特别需求保持 `1.0` 并按模型数据配置。霰弹枪的 `m_reloadState` 分段换弹不走这套整体时长同步，需要按实际模板测试，不能按普通弹匣枪承诺效果。

当前换弹声音最多拆 8 条，单条 `帧号:路径` 缓冲为 64 字节，包含结束符；长路径/过多事件会截断。还应核对整串的调用方长度，不能仅验证单条。其他多音效列表也先按不超过 8 条处理。不要改坏作者资源路径来绕过限制；超限时提出缩短资源命名或调整需求的具体方案。

### 5.6 消音器、刀与手雷

仅 `m4a1/usp` 模板按现有变体逻辑配置消音状态。缺少变体字段会回落普通字段；没有独立变体不必机械复制整套字段。

- 主配置支持 `wmodel_silencer`、`firesound_silencer`；不凭后缀习惯发明 `vmodel_silencer`。
- 瞄准支持两种前缀的 `model/animmove/animtime/animfire` 加 `_silencer`。
- 检视支持 `inspectseq/inspecttime/inspectsound` 加 `_silencer`。
- 奔跑支持 `runseq/runtime/runin/runinlength/runout/runoutlength` 加 `_silencer`。
- 换弹支持对应序列、时间、声音的变体，按读取代码核对；不要认为所有字段都支持后缀，例如 `reloadfps` 仍读取普通字段。
- 刀距离使用 `knife_range_primary`、`knife_range_secondary`；缺省/空/0 为 48/32，有效 `(0,8192]`，支持小数。不新增已废弃的 `knife_effects/knife_hitgroups` 开关；配置本身不会自动增加爆头倍率或连招。
- `customsoundct/customsoundt` 是刀/手雷的声音目录前缀。当前代码例如把 `weapons/knife/knife_slash1.wav` 的 `knife` 替换成前缀；填 `myknife` 可能得到 `weapons/myknife/myknife_slash1.wav`。必须按替换结果核对实际文件，不能当普通 WAV 路径或随意假设保持原文件名。手雷拉保险音按 `weapons/<前缀>/pinpull.wav` 查找。

源码对照还需留意实现限制：8.4 的奔跑起手在启动计时阶段读取变体字段，但逐 tick 强制起手序列处仍读取普通 `runin`。如果两种消音状态的起手序列不同，不能承诺只填 `runin_silencer` 就一定正确；应标记这个代码层面的限制，询问用户是否接受相同起手、暂不使用该过渡，或另行处理源码。

### 5.7 购买和 Bot

| 文件/字段 | 规则 |
|---|---|
| 买卖根字段 | `buysystem`、`buymode`（`always/buytime`）、`buycommand`、`sellcommand`；不是放进武器节点里 |
| 买卖武器节点 | `useclassname`、`name`、`buyable`、`price`、`sellable`、`sellratio`、`sellratio_other` |
| `price` | 未填会回落脚本 `WeaponPrice` 等来源；不打算免费时不能随手填 0。用户不要购买则明确 `buyable 0` |
| 出售比例 | 按用户方案配置，敌方回收比例未填时回落本队比例；不要凭空设经济数值 |
| Bot 根字段 | `botsystem`、`botmoney`、`botaimcd`、`botruncd`、`botinspectcd`、`botaimtime`；CD/维持时长为秒 |
| Bot 武器节点 | `useclassname`、`botchance`、`botaim`、`botrun`、`botinspect`；范围 0～100 |
| `botchance` | 候选间的相对给予权重，不是独立百分比；0 不给予，多个 100 仍需按总权重分配 |
| Bot 槽位 | 脚本 `bucket`：0 主武器、1 副武器、2 刀、3 雷、4 C4；缺少脚本槽位不会参与正常选择 |

只在武器本身已配置对应功能时给 Bot 开启该行为。用户不要 Bot 使用此武器时，各项可为 0。用户希望 Bot 使用而现有 `botsystem 0` 时，解释全局开关的影响后按其选择处理，不只改权重就宣称已启用。

### 5.8 下载配置

`Download.cfg` 是逐行路径文本，不是 KeyValues：无根节点、无大括号、路径不包引号、注释独占一行用 `//`。目录会递归扫描，或逐个列文件；当前允许 `vtf vmt vtx mdl vvd phy wav mp3`。

只添加本武器及实际共享依赖，避免扫描整个 `models/` 或 `materials/`。保留现有项目，尤其插件已有的 `materials/zoom/zoomin.vmt`、`.vtf`。预缓存不等于加入下载表，也不等于文件已经复制到服务器。武器脚本 `.txt` 不在此模块的下载后缀白名单内，不要放进去就承诺客户端能下载脚本。

本地客户端已经有资源时可无下载表，但多人服务器必须按部署方式处理客户端资源。FastDL 地址和上传位置由服务器实际设置决定；没有这类访问条件时提供上传清单，不编造下载站或声称已上传。

## 6. 写入、交付和测试

资料齐全且用户已要求你配置指定目录时，直接完成已授权范围内的写入，不再逐文件问“要不要我继续”。编辑前备份实际被修改的现有文件，只合并本武器和用户需要的关联项，保留其他武器、全局参数、注释和未知第三方脚本字段。

没有服务器目录但其他资料齐全时，必须生成独立安装包，包含配置、新建脚本、改名后的模型及必需资源、下载路径、路径变更对照和安装说明，按 [模型独立化与安装包.md](模型独立化与安装包.md) 的目录结构交付，不能只口头列参数。无文件写入能力时交付可保存的完整文件内容及目录清单。关键资料待补时完成不依赖它的部分，并准确说明“已生成，尚未安装”或“部分完成”。不要向猜测的服务器目录写入，也不在正式配置中留下 `待填写`、`xxx.mdl` 等占位值冒充可用配置。

生成完成后，按《AI自检与修复指南.md》的静态检查项自检。新增配置可以直接修正生成过程中的错误；排查用户现有故障时，遵循该指南的先建议、征求意见再修复流程。

交付应包含：实际修改/生成的文件及位置、资源安装路径、启用和关闭了哪些功能、已核验内容、尚缺资料、简短测试步骤。八个配置文件都要说明本武器是否有新增/合并内容；无变更的说明原因，不为凑文件而覆盖原文件。

重载与测试注意：

1. 新增命令和插件脚本缓存需要重新加载插件。给出实际插件文件对应的重载命令；未知插件文件名时先让用户通过 `sm plugins list` 查明，不只给一个缺参数的 `sm plugins reload`。
2. 下载表在地图开始处理，新增下载资源要经过换图/重启地图等相应流程。脚本和客户端资源还可能有引擎缓存，脚本修改后建议完整重启测试服务器并重新连接验证，不能保证仅重载插件能刷新全部脚本数据。
3. 用户重新获取武器，先验证发枪与正常模型，再测射击、空枪、换弹、检视、奔跑、瞄准、掉落、购买和 Bot。未启用项不用测试。
4. 检视测试包含攻击冷却中按 F、冷却后动画仍在尾段时按 F、空弹匣时按 F、攻击打断检视。换弹声音测试包含满弹匣按 R、无备弹按 R、空仓和非空仓换弹。
5. 静态检查通过只说明已检查的文件和关联正确；没有启动实际 CS:S 环境就注明尚未游戏内实测，不称“保证可用”。服务器重载、换图等操作按用户安排执行，不把文档生成当作已经完成线上部署。
