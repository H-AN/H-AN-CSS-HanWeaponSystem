# 将原版替换模型转为独立新武器，并生成安装包

供配置 AI 执行，配合 [AI武器配置指南.md](AI武器配置指南.md)。这里说明实际资源处理和交付要求；没有给出某把武器的资源时，不能声称已经为该武器完成模型改名。

## 1. 先识别替换包和目标位置

先问清楚服务器 `cstrike` 是否存在并可访问；没有就记录安装包输出位置，继续完成配置。检查资源包是否沿用原版路径、文件名或共享材质/声音，例如 `models/weapons/v_rif_ak47.mdl`。这是模型原本用于替换 AK47 的线索，不代表用户要覆盖原版 AK47，也不能单凭该名字确定用户要求的武器槽位。

将包内相对路径与所选脚本模板的 `viewmodel/playermodel` 等引用、现有服务器资源、其他已配置新武器对照。相同路径下自定义文件可能替换原版，也可能与其他新武器相冲突。不能只看模型，忽略材质和声音的同名冲突。

确定唯一英文标识，例如 `han_my_rifle`，默认由它建立独立目录和模型名。无需让新手逐个起文件名；给出一套统一命名方案，用户接受后直接处理。保留原资源包，向新输出位置复制并改名，不移动或覆盖原版文件。

## 2. 建立旧路径 → 新路径对照并处理依赖

下面仅演示命名规则，实际输出必须使用本次武器真实名称和存在的文件：

| 原包路径 | 独立武器路径示例 |
|---|---|
| `models/weapons/v_rif_ak47.mdl` | `models/han_weapons/han_my_rifle/v_han_my_rifle.mdl` |
| `models/weapons/v_rif_ak47.vvd` | `models/han_weapons/han_my_rifle/v_han_my_rifle.vvd` |
| `models/weapons/v_rif_ak47.dx90.vtx` | `models/han_weapons/han_my_rifle/v_han_my_rifle.dx90.vtx` |
| 对应 W/瞄准/消音模型及伴随文件 | 同目录中不同的 `w_...`、`v_..._aim` 等实际使用名称 |
| 冲突的自定义材质目录 | `materials/models/han_weapons/han_my_rifle/...` |
| 冲突的自定义音效目录 | `sound/weapons/han_my_rifle/...` |

操作要求：

1. 先收集模型、材质、声音和共享依赖的真实引用，建立完整映射。已有独立目录且无冲突的资源可以保留，不为改名而改名；原版替换模型则建立独立模型路径和名称。
2. 同一模型的 `.mdl/.vvd/.dx90.vtx/.dx80.vtx/.sw.vtx/.phy` 等按实际存在及需要保持新 basename 一致，多段后缀不能误改成 `v_han_my_rifle.vtx`。外部动画、模型包含关系按真实依赖处理，不凭后缀列表猜测全套文件。
3. 文件系统改名与模型内部重定位是两件事。检查 MDL 内材质搜索路径、纹理名、包含模型/动画引用、相关模型名及事件引用；移动自定义材质后更新必要的模型内部引用。使用理解该模型格式的工具或可用源文件重编译，不对 MDL/VVD/VTX 进行通用文本替换，不任意改字节长度或破坏配套校验关系。
4. 检查 VMT 中 `$basetexture`、`$bumpmap`、`$detail`、掩码纹理及 `include` 等实际使用项。材质键中的资源路径通常不带 `materials/` 和扩展名，按原字段格式更新；不要机械套用 Download.cfg 的路径格式。保留确认需要的游戏自带共享材质，复制并独立化有覆盖风险的自定义同名文件。
5. 声音改名/搬目录时更新插件声音字段、脚本/声音定义及模型中实际使用的事件或别名引用。若事件引用的是声音别名，不能把任意 WAV 路径直接塞进原别名字段就认定有效。
6. 更新新武器脚本 `viewmodel/playermodel` 及实际使用的 `AddonModel` 等模型引用，再更新主配置 V/W、瞄准模型、消音模型和全部相关声音字段。模板里未使用的原版辅助模型引用不要误改成不存在的自定义文件。
7. 不存在可靠的内部重定位工具/可编译源文件时，先明确已完成的外层复制改名和未解决的内部引用，提出可行的工具/源文件需求或保留已确认无冲突的共享路径方案。不能把缺依赖或仍会覆盖原版的包称为“完整独立武器”；涉及用户取舍时询问其意见。
8. 输出对照表并验证所有新引用可解析。具备实际模型查看/游戏环境时再验证模型、纹理、动画与声音；只有文件检查时注明内部哪些内容已验证、哪些尚不能验证。

## 3. 用户没有武器脚本时，直接创建

读取 [原版武器脚本模板/说明.md](原版武器脚本模板/说明.md)，按已确认的 `classname` 复制对应完整模板，重命名为 `scripts/<useclassname>.txt`，不能沿用原版文件名覆盖原枪。

由 AI 修改真实新模型路径、用户选择的弹匣容量 `clip_size`、必要弹药类型、用户明确要求的基础属性和价格；保留其他模板结构。完全无弹药机制的 `None` 写在对应弹药类型字段，`clip_size` 使用整数，具体规则见主指南。新脚本的 `bucket`、实体模板与武器槽位应一致。

模板库是输入资料，不是输出安装文件。安装包内仅包含本次新建/确实需要的脚本，不把 29 份原版脚本一起复制进服务器。

## 4. 没有服务器目录：生成独立安装包

用户没有现成服务器时，资料齐全就直接在已知可写的输出目录生成如下结构；无法写文件的聊天 AI 提供可保存的文件内容及完整清单：

```text
安装包_<本次武器标识>/
├─ 安装说明.md
├─ 路径变更与资源清单.md
└─ cstrike/
   ├─ addons/sourcemod/configs/HanWeaponSystem/
   │  ├─ HanWeaponData.cfg
   │  ├─ HanWeaponZoomData.cfg
   │  ├─ HanWeaponInspectData.cfg
   │  ├─ HanWeaponRunData.cfg
   │  ├─ HanWeaponEmptyReloadData.cfg
   │  ├─ HanWeaponBuyData.cfg
   │  ├─ HanWeaponBotData.cfg
   │  └─ Download.cfg
   ├─ scripts/<useclassname>.txt
   ├─ models/han_weapons/<本次标识>/...
   ├─ materials/models/han_weapons/<本次标识>/...
   └─ sound/weapons/<本次标识>/...
```

目录名占位符必须替换为真实值。无此类资源或使用另一已确认独立路径时，省略空目录或按真实结构生成，不伪造文件。配置文件用真实可解析结构，关闭不适用功能；对已安装服务器使用的全局开关未知时，说明本安装包的初始默认方案及合并方法，不能承诺直接覆盖既有配置安全。

`安装说明.md` 必须区分两种安装方式：全新配置可采用本包完整配置；已有武器配置则只合并本武器节点及缺少的下载行，不覆盖其他武器与全局设置。说明 HanWeaponSystem 插件是前置条件，本包没有安装插件就不能独立运行。

## 5. 有服务器目录：合并安装并保留输出记录

读取实际配置，备份本次要改的文件，按用户已授权的添加武器范围复制独立资源、新建脚本和合并节点。写入前检查目标资源名是否已被其他武器使用；若有冲突，选新标识并同步重建映射，不覆盖它。

不把资源包原始的 `models/weapons/...` 替换目录原样整包覆盖到服务器。现有目录中已经发生原版覆盖时，先说明当前情况和本次独立化方案，不能假装创建新目录就自动恢复了旧版原枪文件。

## 6. 自动生成下载路径并自检

- 从实际交付资源清单生成 Download.cfg。模型及其伴随文件、VMT/VTF 和声音都要覆盖，包含真正的共享自定义依赖；目录项或逐文件项均可，去重且不扩大到全部游戏资源。
- 模型/材质路径从 `models/`、`materials/` 开始；下载声音从 `sound/` 开始。插件播放声音字段则省略 `sound/`，二者不能混淆。
- 使用改名后的最终路径，不留下旧原版替换路径。脚本 `.txt` 与外部动画等不在当前下载白名单中的文件，需要按实际支持的部署方式另行安排，不能靠写一行不存在或不支持的下载项解决。
- 插件的通用机瞄材质等前置资源需要实际存在；说明来源和安装要求，不能仅列下载路径就称已经打包。
- 检查每条新引用在输出包/已知游戏搜索路径能找到对应文件，下载表覆盖交付中的客户端资源，脚本与各配置全部指向相同新标识。
- 交付时报告：脚本从哪个模板生成、弹匣与弹药机制、旧新路径映射、配置位置、资源位置、下载项、已做的检查、待完成事项及重新加载/重新取枪/换图测试步骤。
